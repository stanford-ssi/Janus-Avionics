# Pushing to Github

On the Satellite Avionics Team, we follow the industry standard pull request structure when updating our primary repositories for avionics work. This process, conceptually, is performed in the following steps:

1. **Create a Branch**: Instead of modifying the main project directly, a developer branches off to work on a specific feature or bug fix.

2. **Commit and Push**: The developer commits their changes and pushes their isolated branch to a version control platform like GitHub or Bitbucket.

3. **Open the PR**: The developer opens a pull request, formally requesting to merge their branch into the main project.

4. **Review and Discuss**: Team members review the code, suggest improvements, and ensure tests pass.

5. **Merge**: Once approved, the changes are merged into the main codebase
